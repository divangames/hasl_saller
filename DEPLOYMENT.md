# OUTMAX SALE — контракт переноса дизайна

Прототип повторяет пользовательские маршруты рабочего Next.js-сайта `sale.outmaxshop.ru` и может работать в двух режимах:

- локально и на GitHub Pages — hash-маршруты (`#catalog/sneakers`);
- на основном домене — чистые маршруты (`/catalog/sneakers`).

При статическом размещении на отдельном домене сервер должен отдавать `index.html` для всех перечисленных ниже маршрутов. В текущем Next.js-развёртывании каждый маршрут уже обрабатывается приложением.

## Маршруты

| Экран | Production URL |
| --- | --- |

| Кроссовки | `/catalog/sneakers` |

## Что переносить без изменений

- `styles.css` — визуальные токены, адаптивная сетка, safe-area, состояния компонентов и motion-система.
- `ui-refinement.css` — обновление интерфейса; подключается после `styles.css`. Включает читаемые состояния, мобильную прокрутку главной и увеличенные зоны нажатия.
- `product-photos.js` — снимок галерей из официального YML, подключается перед `app.js`. Обновление: `pwsh -File scripts/sync-product-photos.ps1`. Сопоставление по артикулу, все уникальные `picture` в порядке фида. Отсутствующие в фиде товары сохраняют прежние фото; скрипт перечисляет их в предупреждении. Цены, размеры и наличие не импортируются.
- `product-stock.js` — снимок размеров и остатков из `https://outmaxshop.ru/yml/all_yandex.yml`, подключается перед `app.js`. Обновление: `pwsh -File scripts/sync-product-stock.ps1`. Связка: `group_id` (либо `vendorCode`) + `param[name="Размер"]`, количество из `count`. Дата выгрузки сохранена в `feedDate`. Это снимок, а не онлайн-резервирование; запускайте обновление перед публикацией. Неизвестные остатки не считаются нулевыми. Стоимость товаров и отправка заказов не меняются.
- `images/`, `assets/figma/` — локальные изображения и SVG; URL в JavaScript вычисляются относительно `app.js`, поэтому вложенные маршруты не ломают ассеты.
- Разметку функций `discountDashboard`, `quickSectionsNav`, `productCard`, `filterDrawer` и экранов из `app.js`.
- CSS-классы `sticky-head`, `quick-sections`, `product-grid`, `product-view`, `filter-drawer`, `bottom-nav` — на них завязаны адаптивность и анимации.

## Состояние и данные

`product-details.js` подключается перед `app.js` и содержит индивидуальные описания, пол, характеристики, фото и остатки из `all_yandex.yml`. Обновление из скачанной XML-выгрузки: `pwsh -File scripts/sync-product-details.ps1 -FeedPath <путь>`. Импорт включает исходные артикулы и 24 дополнительные модели обуви (12 женских и 12 мужских). Цены исходных товаров сохраняются; дополнительные товары используют цену выгрузки. Для отсутствующего описания показывается честное пустое состояние. Женская сетка 36–41 и мужская 40–46 выбираются строго по полю «Пол»; для неизвестного пола и детской обуви взрослая сетка не подставляется.

- Данные товаров в production должны приходить с сервера, но сохранять поля `id`, `article`, `section`, `name`, `price`, `oldPrice`, `image`, `gender`, `sizes`, `brand`, `gallery`.
- Корзина и оформление в прототипе локальные. В Next.js их нужно подключить к текущему production store/API, не меняя DOM-контракт компонентов.
- Возврат из товара использует History API и восстанавливает раздел, фильтры, количество показанных карточек и точную позицию прокрутки.

## Motion

- Пружинный вход экранов и bottom sheet фильтра выполняется через `transform` и `opacity`.
- Элементы управления получают короткое сжатие, rubber-band смещение за пальцем и пружинный возврат через Web Animations API.
- `prefers-reduced-motion: reduce` отключает декоративное движение.

## Проверка после интеграции

1. Открыть каждый маршрут напрямую и обновить страницу.
2. Проверить загрузку всех `/images/*` и `/assets/figma/*` без 404.
3. На мобильном открыть товар из середины каталога, нажать «Назад» и убедиться, что восстановилась точная позиция.
4. Проверить три фиксированных таба категорий, фильтр, корзину и оформление.
5. Проверить iPhone safe-area, Android Chrome и режим уменьшения движения.
