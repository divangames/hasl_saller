# CURSOR AGENT — ПОЛНЫЙ ПЕРЕНОС ДИЗАЙНА И UI/UX

## ТВОЯ РОЛЬ

Ты — Principal Frontend Engineer, Senior UI/UX Designer, Software Architect и QA Engineer.

Работай в режиме полноценного автономного агента. Не ограничивайся анализом, рекомендациями или генерацией отдельных компонентов.

**Твоя задача — реально перенести весь дизайн исходного проекта на мой работающий сайт, не затрагивая его бэкенд и бизнес-логику.**

Используй доступные инструменты Cursor, терминал, браузерное тестирование, MCP и релевантные Skills.

## 1. ИССЛЕДОВАНИЕ И ЗАПУСК

Начни с исследования текущего рабочего окружения.

1. Найди проект, содержащий `start.bat`.
2. Прочитай `start.bat` и проверь его действия перед запуском.
3. Запусти файл через терминал Cursor, если запуск безопасен.
4. Определи адрес локального сервера и открой приложение.
5. Изучи структуру исходного проекта.
6. Определи технологии, библиотеки, стили и зависимости.
7. Найди целевой сайт в рабочем окружении.
8. Исследуй его frontend, backend и действующие интеграции.
9. Составь карту соответствия страниц исходного проекта и целевого сайта.

Если обнаружено несколько проектов, определяй их назначение по конфигурациям, рабочим папкам и документации. Не меняй случайный проект.

При обнаружении неясностей, не блокирующих разработку, принимай обоснованные решения самостоятельно.

## 4. ПОЛНОСТЬЮ ПЕРЕНЕСИ ДИЗАЙН

Требуется **полноценная замена визуального интерфейса**, а не косметический редизайн.

Перенеси:

1. Всю систему оформления.
2. Структуру страниц.
3. Систему навигации.
4. UI-компоненты.
5. Типографику.
6. Анимации.
7. Графические ресурсы.
8. Адаптивную вёрстку.
9. Состояния элементов.
10. Визуальную логику взаимодействия.

По возможности сохраняй оригинальные пропорции, расстояния и визуальную композицию.

Не придумывай другой дизайн, если в исходном проекте уже существует готовое решение.

Не заменяй рабочие части целевого сайта демонстрационными заглушками.

Новые frontend-компоненты должны использовать существующие данные и обработчики сайта.

Если интерфейс содержит функции, которых нет в исходном дизайне, оформи их в рамках перенесённой дизайн-системы, сохранив их поведение.

## 5. БЭКЕНД И БИЗНЕС-ЛОГИКУ НЕ ТРОГАТЬ

**ЭТО АБСОЛЮТНОЕ ОГРАНИЧЕНИЕ.**

Не изменяй:

- Backend.
- API endpoints.
- API contracts.
- Базу данных.
- Миграции.
- Авторизацию.
- Регистрацию.
- Серверные обработчики.
- Бизнес-логику.
- Логику сохранения данных.
- Логику загрузки данных.
- Существующие интеграции.
- Права доступа.

Допускается изменение frontend-оболочки, включая JSX/TSX, HTML, CSS, SCSS, визуальные компоненты и анимации.

При этом сохраняй существующие обработчики событий, параметры API-запросов и пользовательские сценарии.

Если UI-компонент одновременно содержит интерфейс и бизнес-логику, отделяй презентационную часть максимально безопасно.

**Нельзя переписывать бизнес-логику ради соответствия дизайну.**

## 6. CURSOR RULES

Изучи существующие правила в `.cursor/rules/`, `AGENTS.md` и другой проектной документации.

Не удаляй и не перезаписывай действующие правила.

Соблюдай следующие требования:

- Комментарии в коде — на русском языке.
- Код должен быть понятным и поддерживаемым.
- Не дублируй компоненты без необходимости.
- Используй существующий технологический стек.
- Не устанавливай лишние зависимости.
- Не выполняй массовую перезапись без анализа.
- Не отключай линтеры и тесты ради успешной сборки.
- Не оставляй временный отладочный код.
- Обновляй `CHANGELOG.md`.
- Сохраняй совместимость с существующими `.bat`-скриптами.
- Не меняй механизм деплоя без необходимости.

При необходимости создай дополнительное правило Cursor для визуальной разработки, не нарушая существующие.

## 7. АДАПТИВНОСТЬ

Полностью адаптируй интерфейс под:

- 320px.
- 375px.
- 390px.
- 430px.
- 768px.
- 1024px.
- 1366px.
- 1440px.
- 1920px.
- 2560px и выше.

Проверь вертикальную и горизонтальную ориентации смартфонов.

Удели особое внимание iPhone 11–17 Pro Max.

Используй современные технологии адаптивной вёрстки:

- Flexbox.
- CSS Grid.
- `clamp()`.
- Fluid typography.
- Container Queries.
- Safe-area.
- Responsive images.

На мобильных устройствах интерфейс должен быть полноценным, а не просто уменьшенной десктопной версией.

Не допускаются наложения, обрезания, мелкие интерактивные элементы и горизонтальный скролл из-за ошибок вёрстки.

## 8. ПРОИЗВОДИТЕЛЬНОСТЬ

Сайт должен одинаково хорошо работать на слабых, средних и современных устройствах.

Оптимизируй:

- CSS.
- Загрузку шрифтов.
- Изображения.
- Анимации.
- Размеры JS-бандлов.
- Повторные рендеры компонентов.
- Скорость отображения интерфейса.
- Layout stability.
- Плавность взаимодействий.

Не используй тяжёлые библиотеки там, где достаточно CSS.

Для анимаций предпочитай `transform` и `opacity`.

Поддерживай `prefers-reduced-motion`.

## 12. GIT И БЕЗОПАСНОСТЬ

Перед внесением изменений:

- Проверь `git status`.
- Не перезаписывай существующие незакоммиченные изменения.
- Создай безопасную контрольную точку.
- Работай в отдельной ветке, если проект использует Git.

Не выполняй `git reset --hard`, `git clean -fd` и другие разрушительные команды без явного разрешения.

Не выполняй автоматическую публикацию в production без соответствующего разрешения.
